# Умный подбор подрядчиков · HackAlem

Рабочее демо команды Nuravi: до трёх подрядчиков из предоставленного каталога Казахстана с индивидуальными, проверяемыми объяснениями. Пользователь задаёт город, дату, формат, категорию, бюджет и, при необходимости, языки, часы и пожелание к подрядчику. Блок «Почему рекомендован» показывает основания выбора; топ-1 сравнивается с топ-2 по реальным компонентам оценки. Каталог не дополнялся новыми профилями.

## Запуск

Windows PowerShell из папки репозитория:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1
```

Linux/macOS или Git Bash:

```sh
sh run.sh
```

Откройте **http://127.0.0.1:8501**. Скрипты создают локальную `.venv`, устанавливают зависимости и запускают Streamlit на localhost. Нужен Python 3.10+; проверено на Python 3.12.10. Первая установка требует интернета; подбор работает локально. Команда PowerShell выше разрешает выполнение только для запущенного процесса и не меняет политику системы. Другой порт: `powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 --server.port 8502` или `sh run.sh --server.port 8502`. Остановка: Ctrl+C.

Ручная установка без `uv`:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py --server.address 127.0.0.1
```

Ключи API, переменные окружения и `.env` не требуются. Приложение не отправляет профили внешним сервисам; телеметрия Streamlit отключена.

## Демо для жюри

Сценарий выбирается кнопками «Быстрые примеры» над формой и сразу загружает параметры и результат. Обычные изменения применяются кнопкой «Подобрать подрядчиков». Язык и длительность находятся в раскрываемом блоке. Первый сценарий открыт по умолчанию.

| Сценарий | Параметры | Ожидаемый результат на исходном CSV |
| --- | --- | --- |
| Плотная категория | Алматы, Ведущий, корпоратив, 14.11.2026, 1 500 000 ₸, русский, 6 ч | 4 подходят, топ-3: HK-44923, HK-29829, HK-44733 |
| Другая дата | Те же параметры, 15.11.2026 | 6 подходят, топ-3: HK-88430, HK-44923, HK-35215 |
| Пожелание | Те же параметры на 15.11.2026, «деловой форум» | Топ-3: HK-88430, HK-44733, HK-44923; показаны совпавшие фразы описаний |
| Редкая категория | Алматы, Флорист, корпоратив, 10.10.2026, 300 000 ₸, русский, 6 ч | 1 вариант: HK-39372; max_hours=null, цена восстановлена |
| Никто не проходит | Первый запрос с бюджетом 10 000 ₸ | Категория есть, подходящих нет; 10 выше бюджета, 5 заняты, 1 не берёт формат; причины пересекаются |
| Категории нет | Зарубежье, Флорист, корпоратив, 14.11.2026, 300 000 ₸ | Такой категории в городе нет; отличается от отказа по условиям |

За 30 секунд: покажите первую карточку → смените дату → покажите пример с пожеланием и совпавшую фразу → покажите редкую категорию или пустой результат. В блоке «Что меняется на другой дате» названы вошедшие и выбывшие кандидаты и показаны их календари. На 14 ноября заняты 5 ведущих Алматы, на 15 ноября — 2.

Повторить все сценарии без интерфейса:

```sh
.venv/bin/python -m matcher.demo
```

На Windows: `.\.venv\Scripts\python.exe -m matcher.demo`.

## Архитектура и карта требований

Два независимых слоя: `matcher/data.py` и `matcher/engine.py` определяют допустимость, порядок и доказательства; `matcher/explain.py` только формулирует факты уже выбранных профилей. `app.py` отображает результаты и аудит. Ядро не импортирует Streamlit и не зависит от сети.

| Требование | Реализация |
| --- | --- |
| CSV, списки через `\|`, нормализация, ошибки | `matcher/data.py` |
| Семь жёстких условий, три исхода, воронка | `matcher/engine.py` |
| Прозрачные баллы, устойчивый порядок | `score`, `select` |
| Сопоставление пожелания с фразами описания | `matcher/text.py` |
| Индивидуальные объяснения, сравнение топ-1/топ-2 и оговорки | `matcher/explain.py` |
| Форма, карточки, отказы, сравнение дат, JSON-аудит | `app.py` |
| Воспроизводимые демо | `matcher/demo.py` |
| Проверки бизнес-логики, загрузки и формы | `tests/` |

Используются Python, Streamlit и стандартные `csv`, `dataclasses`, `Decimal`. Для 66 строк стандартный CSV-парсер позволяет явно контролировать пустые значения без автоматического превращения их в NaN. Pandas приходит как зависимость Streamlit для таблиц, но бизнес-логика от него не зависит. Точные денежные вычисления и сортировка выполняются с Decimal; округление применяется только для отображения.

## Жёсткая фильтрация

1. Точное совпадение выбранной категории с одним элементом `categories`. «Ведущий церемонии» не равен «Ведущий».
2. Совпадение города. Пробелы, регистр, Unicode и ё/е нормализуются для сравнения.
3. Календарь занятости заполнен, а дата отсутствует в `busy_dates`; разрешены только 23.09.2026–31.12.2026 включительно. Пустой `busy_dates` означает, что доступность неизвестна, поэтому профиль не выдаётся как свободный.
4. `price_from_kzt <= budget`.
5. Тип мероприятия присутствует в `event_formats`.
6. Все выбранные пользователем языки присутствуют в `languages`.
7. Если часы указаны и `max_hours` известен, `hours <= max_hours`.

`max_hours=null` означает, что ограничение неприменимо. Профиль проходит, но подтверждения длительности и баллов за этот фактор не получает. Неуказанные язык и часы не ограничивают поиск. Занятые профили никогда не попадают в рекомендации. Нулевая/отрицательная/нечисловая/бесконечная сумма бюджета возвращает понятную ошибку валидации; аналогично проверяются часы. В UI ноль часов означает «не указано», в ядре это `None`.

Три исхода явно различаются: `found`, `no_category`, `no_matches`. Если в городе вообще менее трёх профилей, это видно по счётчику; если часть отфильтрована, видны причины. Корректно подходящие ниже топ-3 не выдаются за отказавших по условиям.

Воронка последовательна: категория → город → доступность → бюджет → формат → язык → длительность. Отдельный подсчёт причин проверяет каждый профиль категории и города по всем условиям одновременно. Поэтому суммы причин могут быть больше числа исключённых профилей. В раскрываемой таблице можно проверить id каждого исключения.

## Формула ранжирования

После фильтрации для каждого кандидата вычисляются факторы от 0 до 1:

| Фактор | Базовый вес | Значение |
| --- | ---: | --- |
| Формат | 25 | 1: подтверждён обязательным фильтром |
| Язык | 20 | 1, если заданы и подтверждены все языки; без запроса фактор исключается |
| Бюджет | 20 | `1 − price_from_kzt / budget` после обязательной проверки бюджета |
| Длительность | 15 | 1 при известном подходящем max_hours, 0 при null; без запроса фактор исключается |
| Пожелание | 20 | Доля слов пожелания, найденных в лучшей фразе description; без пожелания фактор исключается |

`score = 100 × Σ(weight × factor) / Σ(active_weights)`.

При отсутствии необязательных параметров соответствующие веса исключаются и остальные нормируются к 100. В карточке всегда показаны все пять факторов: базовый вклад от 0 до фиксированного веса либо отметка, что параметр не задан и не участвует. При указанной длительности null сохраняет вес в знаменателе, но даёт 0. Оценки рассчитаны для конкретного запроса и не предназначены для сравнения разных запросов.

Бюджет — обязательный фильтр. После него меньшая цена «от» даёт больше баллов по цене. Это не рейтинг качества подрядчика; итоговую стоимость нужно уточнять.

Пожелание сопоставляется с отдельными фразами описания по коротким основам слов. Для слов пожелания учитывается частота в профилях выбранной категории и города; общие слова имеют меньший вес. Выбирается фраза с лучшим покрытием, и она показывается дословно. Формат и язык не добавляют текстовых баллов повторно. Для пожелания с «без» засчитывается только фраза, где «без» тоже написано. Это всё ещё поиск совпадений слов: сложные отрицания и синонимы он не понимает, а неподтверждённый смысл в объяснение не добавляется.

При равном точном score порядок определяется так:

1. Больше подтверждений: формат + число запрошенных языков + известная подходящая длительность + число групп текста.
2. Меньшая цена.
3. Меньшая доля занятых дат в 100-дневном окне.
4. Лексикографический порядок `id`.

Город, категория и доступность не входят в балл. Занятость используется как жёсткий фильтр, её доля — только как поздний tie-breaker по заданию. Порядок не зависит от порядка строк CSV и случайных чисел.

## Объяснения и использование AI

Решение использует объяснимый алгоритм рекомендаций и локальное сопоставление пожелания с текстом. Обучаемой модели, готовых нейросетевых эмбеддингов и LLM в текущей реализации нет. На 66 строках ничего не обучается; запуск и порядок результатов воспроизводимы без API.

Первое предложение карточки называет дату, формат, цену и бюджет. Второе приводит подходящую к пожеланию исходную фразу профиля, если она найдена; без пожелания выбирается информативная фраза описания. Цитата обозначена как слова профиля, а не независимая оценка. Отдельный блок показывает точные условия, нормированные баллы и ограничения.

Для работы не нужен внешний API. Если развивать текстовый поиск, можно сравнить локальный метод с готовыми эмбеддингами на размеченных запросах и сохранить текущие объяснения как проверяемую базу. Модель не должна менять обязательную фильтрацию.

## Данные и ограничения

В `data/contractors.csv` лежит неизменённая копия предоставленного CSV. Бизнес-требования прочитаны из PDF «HackAlem AI: Хакатон-задача: умный подбор подрядчиков». HTML-превью использовано для сверки: 66 уникальных id, множество полностью совпадает с CSV; заголовок подтверждает окно календаря.

Профилей 66, категорий 17 (один профиль может иметь несколько категорий). Городов: Алматы — 50, Астана — 15, Зарубежье — 1. Полностью синтетических профилей 13; восстановленных городов 8; восстановленных цен 18; max_hours отсутствует у 9. Флаги качества показываются на карточках и в JSON-аудите, но не дают бонусов. Имена анонимизированы. Синтетические профили не скрываются и участвуют по тем же правилам.

Занятость известна только на 100 дней. «Свободен» означает отсутствие даты в календаре датасета, не подтверждённую бронь. Профили, цены и описания не проверяются внешними источниками. Декабрьская загруженность и редкие категории закономерно создают пустые результаты.

Повреждённые обязательные поля, цены, часы, флаги, даты и дубли id исключаются с видимым отчётом. Для дублирующего id принимается только первая корректная встреченная запись с уникальным id; повтор помечается ошибкой. Пустое описание разрешено без смысловых баллов. Отсутствие колонок — понятная ошибка загрузки, а не пустая выдача. Пустая ячейка календаря, `[]` и `null` означают неизвестные данные: профиль остаётся в каталоге, но не выдаётся как доступный, а причина явно показывается пользователю. В исходном CSV пустых календарей нет. Если есть ошибки данных, UI сообщает, что результаты относятся к корректной части каталога.

## Проверки

```sh
.venv/bin/python -m pytest -q
```

Тесты проверяют все жёсткие фильтры, три исхода, 1/2/3 результата, пустой календарь, бюджет, языки и длительность, влияние пожелания, ошибки CSV, границы календаря, уникальность объяснений, устойчивость порядка при перемешивании каталога и изменение выдачи по датам. Streamlit AppTest проверяет все шесть демо, ввод запроса и восстановление после ошибки. Документация тестового API: [Streamlit AppTest](https://docs.streamlit.io/develop/api-reference/app-testing/st.testing.v1.apptest).

Результат проверки: **84 теста прошли**. Проверены запуск на Windows, HTTP health endpoint, консольное демо и отображение страницы. Дополнительно просмотрены 10 разных пожеланий на реальных профилях: для каждого варианта проверены бюджет, календарь и дословность показанной фразы. Внешние API и ключи при проверках не использовались.

## Развитие

Следующие содержательные улучшения: подтверждённые календари и цены; параметры аудитории, масштаба и стиля; оценка качества объяснений людьми; проверяемые эмбеддинги с цитатами; версия датасета и сравнение изменений; отдельный API поверх текущего независимого ядра. Регистрация, оплата и бронирование в объём этого демо не входят.
