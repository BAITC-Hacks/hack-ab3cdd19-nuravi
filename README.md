# Умный подбор подрядчиков · HackAlem

Рабочее демо команды Nuravi: до трёх подрядчиков из предоставленного каталога Казахстана с индивидуальными, проверяемыми объяснениями. Пользователь задаёт город, дату, формат, категорию, бюджет и, при необходимости, языки и часы. Под каждой рекомендацией можно проверить исходные поля, вклад факторов и ограничения. Каталог не дополнялся новыми профилями.

## Запуск

Из папки репозитория выполните одну команду:

```sh
sh run.sh
```

Откройте **http://127.0.0.1:8501**. Скрипт создаёт локальную `.venv`, устанавливает зависимости при первом запуске и запускает Streamlit на localhost. Нужен Python 3.10+; проверено на Python 3.12.13. Если установлен `uv`, скрипт автоматически получает Python 3.12. Первая установка требует интернета; после установки подбор полностью работает локально. Для другого порта: `sh run.sh --server.port 8502`. Остановка: Ctrl+C.

Ручная установка без `uv`:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py --server.address 127.0.0.1
```

Ключи API, переменные окружения и `.env` не требуются. Приложение не отправляет профили внешним сервисам; телеметрия Streamlit отключена.

## Демо для жюри

Сценарий выбирается в верхней части левой панели и сразу загружает параметры и результат. Обычные изменения формы применяются кнопкой «Подобрать подрядчиков». Первый сценарий открыт по умолчанию.

| Сценарий | Параметры | Ожидаемый результат на исходном CSV |
| --- | --- | --- |
| Плотная категория | Алматы, Ведущий, корпоратив, 14.11.2026, 1 500 000 ₸, русский, 6 ч | 4 подходят, топ-3: HK-44733 (83.33), HK-27222 (73.33), HK-29829 (69.33) |
| Другая дата | Те же параметры, 15.11.2026 | 6 подходят, топ-3: HK-44733 (83.33), HK-35215 (82.00), HK-75012 (77.33) |
| Редкая категория | Алматы, Флорист, корпоратив, 10.10.2026, 300 000 ₸, русский, 6 ч | 1 вариант: HK-39372; max_hours=null, цена восстановлена |
| Никто не проходит | Первый запрос с бюджетом 10 000 ₸ | Категория есть, подходящих нет; 10 выше бюджета, 5 заняты, 1 не берёт формат; причины пересекаются |
| Категории нет | Зарубежье, Флорист, корпоратив, 14.11.2026, 300 000 ₸ | Такой категории в городе нет; отличается от отказа по условиям |

За 30 секунд: покажите первую карточку → раскройте её факты и баллы → выберите следующую дату → покажите редкую категорию или пустой результат. В блоке «Что меняется на другой дате» есть сравнение календарей конкретных профилей. На 14 ноября заняты 5 ведущих Алматы, на 15 ноября — 2. Изменения топа вызваны календарём; оценки у одного профиля при неизменных остальных параметрах не меняются.

Повторить все сценарии без интерфейса:

```sh
.venv/bin/python -m matcher.demo
```

## Архитектура и карта требований

Два независимых слоя: `matcher/data.py` и `matcher/engine.py` определяют допустимость, порядок и доказательства; `matcher/explain.py` только формулирует факты уже выбранных профилей. `app.py` отображает результаты и аудит. Ядро не импортирует Streamlit и не зависит от сети.

| Требование | Реализация |
| --- | --- |
| CSV, списки через `\|`, нормализация, ошибки | `matcher/data.py` |
| Семь жёстких условий, три исхода, воронка | `matcher/engine.py` |
| Прозрачные баллы, устойчивый порядок | `score`, `semantic_evidence`, `select` |
| Индивидуальные объяснения и оговорки | `matcher/explain.py` |
| Форма, карточки, отказы, сравнение дат, JSON-аудит | `app.py` |
| Воспроизводимые демо | `matcher/demo.py` |
| Проверки бизнес-логики, загрузки и формы | `tests/` |

Используются Python, Streamlit и стандартные `csv`, `dataclasses`, `Decimal`. Для 66 строк стандартный CSV-парсер позволяет явно контролировать пустые значения без автоматического превращения их в NaN. Pandas приходит как зависимость Streamlit для таблиц, но бизнес-логика от него не зависит. Точные денежные вычисления и сортировка выполняются с Decimal; округление применяется только для отображения.

## Жёсткая фильтрация

1. Точное совпадение выбранной категории с одним элементом `categories`. «Ведущий церемонии» не равен «Ведущий».
2. Совпадение города. Пробелы, регистр, Unicode и ё/е нормализуются для сравнения.
3. Дата отсутствует в `busy_dates`; разрешены только 23.09.2026–31.12.2026 включительно.
4. `price_from_kzt <= budget`.
5. Тип мероприятия присутствует в `event_formats`.
6. Все выбранные пользователем языки присутствуют в `languages`.
7. Если часы указаны и `max_hours` известен, `hours <= max_hours`.

`max_hours=null` означает, что ограничение неприменимо. Профиль проходит, но подтверждения длительности и баллов за этот фактор не получает. Неуказанные язык и часы не ограничивают поиск. Занятые профили никогда не попадают в рекомендации. Нулевая/отрицательная/нечисловая/бесконечная сумма бюджета возвращает понятную ошибку валидации; аналогично проверяются часы. В UI ноль часов означает «не указано», в ядре это `None`.

Три исхода явно различаются: `found`, `no_category`, `no_matches`. Если в городе вообще менее трёх профилей, это видно по счётчику; если часть отфильтрована, видны причины. Корректно подходящие ниже топ-3 не выдаются за отказавших по условиям.

Воронка последовательна: категория → город → доступность → бюджет → формат → язык → длительность. Отдельный подсчёт причин проверяет каждый профиль категории и города по всем условиям одновременно. Поэтому суммы причин могут быть больше числа исключённых профилей. В раскрываемой таблице можно проверить id каждого исключения.

## Формула ранжирования

После фильтрации для каждого кандидата вычисляются факторы от 0 до 1:

| Фактор | Базовый вес | Значение |
| --- | ---: | --- |
| Формат | 25 | 1: подтверждён обязательным фильтром |
| Язык | 20 | 1, если заданы и подтверждены все языки; без запроса фактор исключается |
| Бюджет | 20 | `price_from_kzt / budget`, то есть `1 − (budget − price) / budget` |
| Длительность | 15 | 1 при известном подходящем max_hours, 0 при null; без запроса фактор исключается |
| Текст | 20 | Доля подтверждённых групп «формат» и каждого запрошенного языка в description |

`score = 100 × Σ(weight × factor) / Σ(active_weights)`.

При отсутствии необязательных параметров соответствующие веса исключаются и остальные нормируются к 100. При указанной длительности null сохраняет вес в знаменателе, но даёт 0. Оценки рассчитаны для конкретного запроса и не предназначены для сравнения разных запросов.

Бюджетный фактор предпочитает цену ближе к верхней границе заданного бюджета; более дешёвый вариант не получает автоматического первого места. Это прямо заданная эвристика, **не утверждение, что дорогой подрядчик лучше**. Цена «от» не гарантирует окончательную стоимость.

Локальное текстовое сопоставление использует явные основы слов: например, `корпоратив`, `свад`, `конференц`/`форум`, `юбиле`, `русск`, `казах`, `англий`. В аудите указаны совпавшие слова и исходный `description`. Каждая группа засчитывается максимум один раз, повторение ключевого слова баллы не увеличивает. Рекламные «лучший», «топ», отзывы и обещания не создают оценку надёжности. Стиль, масштаб, тип аудитории и опыт могут читаться в исходном описании, но не получают бонусы: у запроса нет параметров, позволяющих объективно сопоставить их. Словарь намеренно консервативен; полное семантическое понимание не заявляется.

При равном точном score порядок определяется так:

1. Больше подтверждений: формат + число запрошенных языков + известная подходящая длительность + число групп текста.
2. Меньшая цена.
3. Меньшая доля занятых дат в 100-дневном окне.
4. Лексикографический порядок `id`.

Город, категория и доступность не входят в балл. Занятость используется как жёсткий фильтр, её доля — только как поздний tie-breaker по заданию. Порядок не зависит от порядка строк CSV и случайных чисел.

## Объяснения и использование AI

Решение использует объяснимый алгоритм рекомендаций и локальное словарное сопоставление текста. Обучаемой модели, эмбеддингов и LLM в текущей реализации нет. На 66 строках ничего не обучается. Такой выбор обеспечивает полную воспроизводимость без API.

Первое предложение объясняет соответствие конкретным ограничениям: точная цена и бюджет, дата, формат, языки, часы. Второе приводит короткую цитату исходного описания с id источника, поэтому различия между профилями проверяемы. Цитата явно обозначена как слова профиля, а не независимая оценка. Если описание пустое, это сказано прямо, текстовый фактор равен нулю.

Шаблоны являются постоянным автономным fallback-режимом. Для работы не нужен внешний API, следовательно его недоступность никак не влияет на результат. Опциональный LLM-слой не добавлялся, поскольку существующей API-интеграции не было. При расширении генератор должен получать только уже отфильтрованные профили и разрешённые факты, с проверкой ответа и откатом на текущие шаблоны; фильтрацию и сортировку менять нельзя.

## Данные и ограничения

В `data/contractors.csv` лежит неизменённая копия предоставленного CSV. Бизнес-требования прочитаны из Word-документа «HackAlem AI: Хакатон-задача: умный подбор подрядчиков». HTML-превью использовано для сверки: 66 уникальных id, множество полностью совпадает с CSV; заголовок подтверждает окно календаря.

Профилей 66, категорий 17 (один профиль может иметь несколько категорий). Городов: Алматы — 50, Астана — 15, Зарубежье — 1. Полностью синтетических профилей 13; восстановленных городов 8; восстановленных цен 18; max_hours отсутствует у 9. Флаги качества показываются на карточках и в JSON-аудите, но не дают бонусов. Имена анонимизированы. Синтетические профили не скрываются и участвуют по тем же правилам.

Занятость известна только на 100 дней. «Свободен» означает отсутствие даты в календаре датасета, не подтверждённую бронь. Профили, цены и описания не проверяются внешними источниками. Декабрьская загруженность и редкие категории закономерно создают пустые результаты.

Повреждённые обязательные поля, цены, часы, флаги, даты и дубли id исключаются с видимым отчётом. Для дублирующего id принимается только первая корректная встреченная запись с уникальным id; повтор помечается ошибкой. Пустое описание разрешено без смысловых баллов. Отсутствие колонок — понятная ошибка загрузки, а не пустая выдача. Пустая ячейка календаря означает неизвестные данные и исключает профиль; явное `[]` означает известный пустой календарь. В исходном CSV пустых календарей нет. Если есть ошибки данных, UI сообщает, что результаты относятся к корректной части каталога.

## Проверки

```sh
.venv/bin/python -m pytest -q
```

Тесты проверяют все жёсткие фильтры, три исхода, 1/2/3 результата и обрезку топа, все профили заняты, пересечение причин, несколько языков, точные граничные значения цены и часов, max_hours=null, неуказанные параметры, нормализацию, ошибки CSV, невозможные числа, окно календаря, игнорирование маркетинговых заявлений, уникальность объяснений, устойчивость сортировки при перемешивании каталога и изменение выдачи на реальных датах. Streamlit AppTest проверяет все пять демо, отправку формы, некорректный бюджет и восстановление после ошибки. Документация используемого тестового API: [Streamlit AppTest](https://docs.streamlit.io/develop/api-reference/app-testing/st.testing.v1.apptest).

Результат проверки: **73 теста прошли**. Проверены настоящий запуск `sh run.sh`, HTTP health endpoint и отображение страницы в Chrome. Внешние API и ключи при проверках не использовались.

## Развитие

Следующие содержательные улучшения: подтверждённые календари и цены; параметры аудитории, масштаба и стиля; оценка качества объяснений людьми; проверяемые эмбеддинги с цитатами; версия датасета и сравнение изменений; отдельный API поверх текущего независимого ядра. Регистрация, оплата и бронирование в объём этого демо не входят.
